Claude Code for marketing agencies: what to build first, and how to keep it safe.

The short answer

Start with a brief file for each client, then build research packs, first drafts, an SEO and AEO audit and monthly reporting, in that order. Keep each client in its own folder with its own connectors, put a person on review before the client sees anything, and use a commercial plan so client data stays out of model training.

Claude Code lets an agency turn its repeatable client work into written instructions and skills that an agent runs while your people approve the results. Here is what to build first, in order, and how to keep every client's data in its own place.

01What is Claude Code, and why do agencies use it?

Claude Code is Anthropic's agentic tool that works inside a project folder: it reads files, edits them, runs commands and connects to other tools. Agencies use it because client work repeats. A brief, a research pack or a monthly report follows the same steps each time, so the steps can be written down once and run by an agent.

Anthropic's Claude Code overview describes it as an agentic coding tool that reads your codebase, edits files, runs commands and integrates with your development tools, available in the terminal, IDE, desktop app and browser1. It was built for software teams. For an agency, the codebase is the client work: briefs, voice rules, research, drafts and the checks that run on them.

Claude Code for a marketing agency is a setup in which each client's work lives in its own folder of written instructions, skills and connectors that an AI agent works through, while the agency's people review and approve everything the client sees.

I run the whole marketing function of an AI startup on Claude Code, alone, and my working notes on running marketing on Claude Code cover that setup in detail. An agency has the same building blocks with one extra job: keeping each client's work and data apart. If agents are new to you, start with the definition of an AI marketing agent.

02Which client work suits Claude Code?

Repeatable work with a clear finished state suits it best: client briefs, research, first drafts, reporting and SEO or AEO audits. In each case the agent gathers and drafts, and a person decides. Work that depends on a relationship, such as pitching, negotiating or handling a client complaint, stays with your people.

03What are the first five workflows to build, in order?

Build in order of risk: work that stays inside the agency first, work that reaches clients next, and work that needs access to client accounts last. A sensible order is the client brief, the research pack, first drafts, the SEO and AEO audit, then monthly reporting. Run each one cleanly for a few weeks before starting the next.

  1. The client brief. One file per client: positioning, audience, voice rules, claims the client can and cannot make, examples of approved work, and who signs off what. Every later workflow reads it first, so it repays the most care.
  2. The research pack. Competitor pages, the questions buyers ask, the current answers in search and AI assistants, and customer reviews, summarised with a link for every claim. Claude Code can run several research questions in parallel through subagents and return only the summaries.
  3. First drafts against the brief. Articles, social posts and emails drafted from the brief and the research pack. Each draft passes a voice check and a source check before an editor reads it. A one-source-in, many-drafts-out version of this is often called a content engine.
  4. The SEO and AEO audit. A repeatable check of a client's pages, structured data and AI crawler access, plus a fixed set of buyer questions tested in AI assistants for answer engine optimisation. The output is a list of fixes your team prioritises.
  5. Monthly reporting. The agent reads analytics and ad platforms through connectors, drafts the numbers and the commentary, and the account manager rewrites the parts that need judgement. It comes last because it needs access to client accounts.

The guide to AI agents for marketing covers the same sequencing question for an in-house team.

04Lane files, skills and connectors: what are they?

A lane file is a plain text instruction file, named CLAUDE.md, that tells the agent how one area of work runs. A skill is a written procedure the agent loads when a task matches it. A connector links the agent to a tool such as an analytics platform or a project board through the Model Context Protocol, usually called MCP.

Lane files

Anthropic's memory documentation says CLAUDE.md files above the working directory load at launch, files in subdirectories load on demand, and each file should target under 200 lines2. In my setup each lane (content, social, search, outbound, events, reporting) has its own CLAUDE.md written like a job description: what the lane owns, what it reads, what finished work looks like and what needs approval. An agency can do the same per service line, with one more layer per client.

Skills

Anthropic's skills documentation says Claude uses a skill when it is relevant, or when you invoke it by name, and that project skills in .claude/skills can be committed so the whole team gets them3. For an agency, that means one version of "how we write a brief" or "how we audit a page" across every account manager, with a history of each change in git. My rule: anything I do twice by hand becomes a skill.

Connectors

Anthropic's MCP documentation says Claude Code can connect to hundreds of external tools and data sources, and tells users to verify they trust each server before connecting it because servers that fetch external content carry prompt injection risk4. Start every connector read-only. Where an agent can write, let it write drafts, never finished work.

05How do you keep each client's data separate?

Give every client its own folder, ideally its own git repository, and start each session inside it. Keep agency-wide rules in a parent folder with no client details, add each client's connectors only to that client's project, block sensitive files, and use a commercial plan so client data stays out of model training.

Claude Code's own behaviour makes this layout work:

  • Working folder. Anthropic's permissions documentation says file reads run without approval inside the working directory and any added directories5, so a session started in one client's folder works on that client by default. Avoid adding a second client's folder to the same session.
  • Shared rules. Because CLAUDE.md files above the working folder load at launch, an agency-wide file in the parent folder reaches every client. Put voice standards and sign-off rules there, never client names, results or data.
  • Memory. Claude Code keeps automatic notes per git repository, according to the memory documentation, so one repository per client keeps those notes apart too.
  • Connectors. The MCP documentation lists three scopes: local and project scope load only in the current project, while user scope loads in every project on the machine. Add client connectors at local or project scope only.
  • Sensitive files. The permissions documentation shows deny rules such as Read(./secrets/**) to stop the agent reading a file or folder. Use one for customer exports and contracts.

The plan matters as much as the folders. Anthropic's data usage documentation says it does not train generative models on code or prompts sent to Claude Code under commercial terms (Team, Enterprise and API), while Free, Pro and Max accounts are used for training when that setting is on, and that local session transcripts are stored in plaintext for 30 days by default6. Client work belongs on a commercial plan, on encrypted laptops, and the client contract should record which tools see its data.

Privacy law follows the client's customers. In New Zealand, the Privacy Commissioner expects a privacy impact assessment before AI tools are used, updated regularly7. In Australia, the OAIC's 2024 guidance recommends that organisations do not enter personal information into publicly available generative AI tools8. Most of the workflows above need no customer personal information at all, which is the simplest protection.

06Where do the review gates go?

Put a gate before each change of audience: after the agent drafts and before an editor reads, after the editor approves and before the client sees, and after the client approves and before anything is published or sent. Automated checks sit at the first gate. People own the other two, and the agent never publishes or sends on its own.

  1. Automated checks. Voice rules, banned claims and a source check on every number, run before a person reads the draft. Drafts that fail are rewritten against the lines that failed.
  2. Editor approval. A named person reads the full draft against the client brief.
  3. Client approval. The client signs off anything published or sent under its name. This is the human in the loop in its plainest form.

Some rules should be enforced by the tool. The permissions documentation says rules are evaluated deny first, then ask, then allow5, so a deny rule on a publishing command holds even if someone adds a broad allow later. The memory documentation adds that Claude treats CLAUDE.md as context, not enforced configuration, and points to hooks to block an action every time. Australian guidance makes the same point about oversight: the National AI Centre says a person should oversee an AI system in a way that matches how much autonomy it has and how high the stakes are9.

One lesson from my own setup: once agents draft faster than people review, approved work queues behind unread work. Reviewing in batches at set times keeps it moving.

07What does Claude Code cost an agency?

Agencies usually pay through Claude Team or Enterprise seats, where Claude Code draws on each member's seat allowance, or through the API, billed per token. Anthropic publishes average figures for software teams only, so price an agency rollout from a small pilot, with your own usage measured from the start.

Anthropic's cost documentation says Team and Enterprise usage draws from a per-seat allowance shared with Claude chat, and reports an average of about US$13 per developer per active day and US$150 to 250 per developer per month across enterprise deployments10. Those are coding figures. Marketing sessions read and write prose, and long sessions cost more because the whole conversation is sent with every request, so clear sessions between unrelated client tasks.

For seat prices in New Zealand dollars, the guide comparing Claude for business and ChatGPT Business costs in NZ sets out each plan. Add reviewer time to the seat cost when you compare it with the hours a workflow saves.

08What should an agency measure?

Measure the work, per workflow, before and after: hours from brief to first draft, how much editors change in each draft, revision rounds with the client, how often drafts fail a review gate, and cost per deliverable including reviewer time. Record a baseline for a month first, or the comparison will rest on memory.

MeasureWhat it tells youWhere to get it
Hours from brief to first draftWhether the workflow saves timeTime tracking, or timestamps on the files
Editor changes per draftWhether the brief and voice rules are good enoughGit history of the draft
Client revision roundsWhether quality reached the clientYour approval tool
Gate failure rateWhich checks catch problems, and which skills need workLogs from the automated checks
Cost per deliverableWhether the economics holdSeat or token spend plus reviewer hours

A falling number of editor changes is usually the earliest sign that a client brief is working.

09When should you bring in a Claude Code consultant?

Bring in a Claude Code consultant when the first workflows run but the setup starts to strain: instruction files that contradict each other, connectors that need write access, several staff who need one shared skills library, or client contracts that require a documented data setup. Before that point, building the first two workflows yourselves teaches the most.

A good consultant builds on your accounts, writes everything down, and leaves your team able to run and change the setup without them. Ask the same questions you would ask an AI agent developer: show me it running, show me the tests, who owns the files, and what does the handover include. The public skill library is a fair way to judge anyone's method before a call, including mine.

11The short version

Write a brief for each client, then build research, drafts, audits and reporting in that order, one workflow at a time. Keep each client in its own folder and repository with its own connectors, on a commercial plan, and put a person at every gate before work reaches the client or the public.

12Questions owners ask

What is Claude Code used for in a marketing agency?

Agencies use Claude Code for repeatable client work: turning discovery notes into a client brief, building research packs, drafting content against the brief, auditing sites for search and AI answers, and writing the monthly report. The agent does the research and the first draft. A person on the agency team reviews each piece before the client sees it, and the client approves anything that is published or sent.

Is Claude Code safe to use with client data?

It can be, with the right plan and setup. Anthropic's documentation says it does not train generative models on code or prompts sent to Claude Code under commercial terms, which cover Team, Enterprise and API use. Keep each client in a separate folder with its own connectors, deny access to sensitive files, and run a privacy impact assessment before client personal information goes near any AI tool.

Do agency staff need to code to use Claude Code?

Most of the setup is plain English: instruction files, client briefs and skill files that describe a procedure step by step. Staff need to be comfortable working in folders and reading what the agent changed. Code matters later, for reporting pipelines, rendering graphics or automated checks, and Claude Code can write much of it, but someone should be able to read it.

How much does Claude Code cost for an agency?

On Claude Team and Enterprise plans, Claude Code usage draws from each member's seat allowance, which is shared with Claude chat. On the API it is billed per token. Anthropic's documentation reports enterprise software teams averaging about US$150 to 250 per developer per month. Marketing use differs, so run a small pilot and measure before rolling it out to every account.

What are Claude Code skills for marketing?

A skill is a folder with a SKILL.md file that describes a procedure, such as writing a brief, auditing a page for AI answers or building a monthly report. Claude Code uses a skill when its description matches the task, or when you call it by name. Project skills can be committed to git, so everyone in the agency runs the same version of each procedure.

When should an agency bring in a Claude Code consultant?

Bring one in when the first workflows run but the setup is starting to strain: instruction files that contradict each other, connectors that need write access, several staff who need one shared skills library, or client contracts that require a documented data setup. A good consultant builds on your own accounts, documents everything and leaves your team able to run and change it.
