营销代理机构如何用 Claude Code：先搭建什么，又如何保证安全。

简短回答

先为每个客户写一份简报文件，然后依次搭建调研资料包、初稿、SEO 与 AEO 审核和月度报告。每个客户放在独立的文件夹里，配各自的连接器；在客户看到任何内容之前安排一个人审核；使用商业版方案，让客户数据不进入模型训练。

01Claude Code 是什么，代理机构为什么用它？

Claude Code 是 Anthropic 推出的智能体工具，在一个项目文件夹里工作：它能读取文件、编辑文件、运行命令，并连接其他工具。代理机构用它，是因为客户工作会重复。一份简报、一份调研资料包或一份月度报告，每次都按同样的步骤走，所以这些步骤可以写下一次，然后交给智能体执行。

Anthropic 在 Claude Code 概览中将它描述为一款智能体编程工具，能读取代码库、编辑文件、运行命令并与开发工具集成，可在终端、IDE、桌面应用和浏览器中使用1。它原本是为软件团队设计的。对代理机构来说，代码库就是客户工作：简报、语调规则、调研、草稿，以及在这些内容上运行的各项检查。

营销代理机构用 Claude Code，是指把每个客户的工作放进各自的文件夹，里面有书面指令、技能和连接器，由 AI 智能体按这些内容推进工作，代理机构的人审核并批准客户看到的每一样东西。

我一个人用 Claude Code 运转一家 AI 初创公司的整个营销职能，用 Claude Code 运转营销的工作笔记详细介绍了这套配置。代理机构用的是同样的基础模块，只多一项任务：让每个客户的工作和数据彼此分开。如果你对智能体还不熟悉，可以先读AI 营销智能体的定义。

02哪些客户工作适合 Claude Code？

最适合的是可重复、完成标准清楚的工作：客户简报、调研、初稿、报告，以及 SEO 或 AEO 审核。在每一项里，都是智能体负责收集和起草，人负责决定。依赖人际关系的工作，比如提案、谈判或处理客户投诉，留给你的团队。

客户工作智能体做什么谁来批准
客户简报把需求调研笔记和客户网站整理成简报草稿客户负责人，然后是客户
调研把竞品页面、搜索结果和评价收集成一份注明来源的资料包策略师
初稿按简报和语调规则起草帖子、文章和邮件编辑，然后是客户
SEO 与 AEO 审核检查页面、结构化数据和 AI 爬虫访问情况，起草修复方案SEO 负责人
月度报告拉取数据并起草分析解读客户经理

客户付钱买的是右边这一栏。营销人的 AI 指南从个人营销人的角度讲了同样的分工。

03最先搭建的五个工作流是什么，按什么顺序？

按风险高低排序：先做留在代理机构内部的工作，再做会到达客户手里的工作，最后做需要访问客户账户的工作。合理的顺序是客户简报、调研资料包、初稿、SEO 与 AEO 审核，最后是月度报告。每一个都稳定跑上几周，再开始下一个。

  1. 客户简报。每个客户一份文件：定位、受众、语调规则、客户可以说和不能说的论断、已获批作品的示例，以及谁签批什么。之后的每个工作流都先读它，所以它最值得下功夫。
  2. 调研资料包。竞品页面、买家会问的问题、搜索和 AI 助手目前给出的答案，以及客户评价，汇总成文，每条论断都附上链接。Claude Code 可以通过子智能体并行运行几个调研问题，只返回汇总结果。
  3. 按简报起草初稿。根据简报和调研资料包起草文章、社交媒体帖子和邮件。每份草稿在编辑阅读之前，都要先通过语调检查和来源检查。一份源文档进、多份草稿出的做法，通常被称为内容引擎。
  4. SEO 与 AEO 审核。对客户的页面、结构化数据和 AI 爬虫访问情况做可重复的检查，再在 AI 助手中测试一组固定的买家问题，用于答案引擎优化。产出是一份修复清单，由你的团队排定优先级。
  5. 月度报告。智能体通过连接器读取数据分析和广告平台，起草数字和分析解读，客户经理改写需要判断的部分。它排在最后，因为它需要访问客户账户。

营销 AI 智能体指南从内部团队的角度讨论了同样的排序问题。

04工作线指令文件、技能和连接器分别是什么？

工作线指令文件是一份名为 CLAUDE.md 的纯文本指令文件，告诉智能体某一块工作如何运作。技能是一份书面流程，任务匹配时由智能体加载。连接器通过模型上下文协议（Model Context Protocol，通常简称 MCP）把智能体接入数据分析平台或项目看板等工具。

工作线指令文件

Anthropic 的记忆文档说明，工作目录上层的 CLAUDE.md 文件在启动时加载，子目录里的文件按需加载，每份文件应控制在 200 行以内2。在我的配置里，每条工作线（内容、社交媒体、搜索、主动外联、活动、报告）都有自己的 CLAUDE.md，按岗位说明的写法来写：这条线负责什么、读取什么、完成的工作是什么样子、哪些事需要批准。代理机构可以按服务线这样做，每个客户再多加一层。

技能

Anthropic 的技能文档说明，Claude 会在相关时使用技能，你也可以按名称直接调用；放在 .claude/skills 中的项目技能可以提交到仓库，让整个团队都能用上3。对代理机构来说，这意味着每位客户经理用的都是同一版“我们怎么写简报”或“我们怎么审核页面”，每次修改都在 git 里留有记录。我的规矩是：凡是我手动做过两次的事，都变成一个技能。

连接器

Anthropic 的 MCP 文档说明，Claude Code 可以连接数百种外部工具和数据源，并提醒用户在连接每个服务器之前先确认可以信任它，因为抓取外部内容的服务器存在提示词注入风险4。每个连接器都从只读开始。智能体有写入权限的地方，只让它写草稿，绝不让它写成品。

05如何让每个客户的数据彼此分开？

给每个客户一个独立的文件夹，最好是独立的 git 仓库，每次会话都在里面启动。代理机构通用的规则放在不含任何客户细节的上层文件夹里，每个客户的连接器只添加到该客户的项目中，屏蔽敏感文件，并使用商业版方案，让客户数据不进入模型训练。

Claude Code 自身的运行机制让这种布局行得通：

  • 工作文件夹。Anthropic 的权限文档说明，在工作目录及任何额外添加的目录内读取文件无需批准5，所以在某个客户文件夹里启动的会话，默认处理的就是这个客户的工作。避免把第二个客户的文件夹加进同一个会话。
  • 共享规则。由于工作文件夹上层的 CLAUDE.md 文件会在启动时加载，放在上层文件夹里的代理机构通用文件会作用于每一个客户。语调标准和签批规则放在这里，客户名称、成果和数据则绝不放进来。
  • 记忆。根据记忆文档，Claude Code 会按 git 仓库分别保存自动笔记，所以每个客户一个仓库，也能让这些笔记彼此分开。
  • 连接器。MCP 文档列出了三种作用域：本地和项目作用域只在当前项目中加载，用户作用域则会在这台电脑上的每个项目中加载。客户的连接器只用本地或项目作用域添加。
  • 敏感文件。权限文档给出了 Read(./secrets/**) 这样的拒绝规则，用来阻止智能体读取某个文件或文件夹。客户资料导出文件和合同都应该设一条。

方案和文件夹同样重要。Anthropic 的数据使用文档说明，在商业条款（Team、Enterprise 和 API）下发送给 Claude Code 的代码或提示词不会用于训练生成式模型，而 Free、Pro 和 Max 账户在相关设置开启时会被用于训练；本地会话记录默认以明文保存 30 天6。客户工作应当在商业版方案上、在加密的笔记本电脑上进行，客户合同也应写明哪些工具会接触其数据。

隐私法跟着客户的顾客走。在新西兰，隐私专员期望企业在使用 AI 工具之前先做隐私影响评估，并定期更新7。在澳大利亚，澳大利亚信息专员办公室（OAIC）2024年的指南建议，组织不要把个人信息输入公开可用的生成式 AI 工具8。上面的大多数工作流根本用不到顾客的个人信息，这本身就是最简单的保护。

06审核关口设在哪里？

在每一次受众变化之前设一道关口：智能体起草之后、编辑阅读之前；编辑批准之后、客户看到之前；客户批准之后、任何内容发布或发送之前。自动检查放在第一道关口，另外两道由人负责，智能体从不自行发布或发送。

  1. 自动检查。在有人阅读草稿之前，先跑语调规则、禁用论断，以及对每个数字的来源检查。未通过的草稿会针对出问题的那几行重写。
  2. 编辑批准。一位指定的人对照客户简报通读整份草稿。
  3. 客户批准。凡是以客户名义发布或发送的内容，都由客户签批。这就是人工把关（human in the loop）最直白的样子。

有些规则应该由工具来强制执行。权限文档说明，规则按“先拒绝、再询问、后允许”的顺序判定5，所以针对发布命令的拒绝规则，即使之后有人加了一条宽泛的允许规则，也依然有效。记忆文档还提到，Claude 把 CLAUDE.md 视为上下文，并不当作强制执行的配置，并建议用钩子（hooks）在每一次都拦截某个操作。澳大利亚的指南在监督问题上观点一致：国家人工智能中心（National AI Centre）表示，人对 AI 系统的监督方式，应当与系统的自主程度和风险高低相匹配9。

我自己的配置给了我一个教训：一旦智能体起草的速度超过人审核的速度，已批准的工作就会排在未读的工作后面。在固定时间集中审核，可以让工作持续推进。

07Claude Code 对代理机构来说成本是多少？

代理机构通常通过 Claude Team 或 Enterprise 席位付费，Claude Code 的用量从每位成员的席位额度中扣除；也可以通过 API 按 token 计费。Anthropic 只公布了软件团队的平均数据，所以代理机构推广之前，先用一个小规模试点来测算价格，从一开始就测量自己的用量。

Anthropic 的成本文档说明，Team 和 Enterprise 的用量从与 Claude 聊天共用的每席位额度中扣除，并给出企业部署中的平均水平：每位开发者每个活跃日约 US$13，每月 US$150 到 25010。这些是编程场景的数字。营销会话读写的是文字，而且长会话成本更高，因为每次请求都会发送整段对话，所以在处理不相关的客户任务之间要清空会话。

想看新西兰元的席位价格，新西兰 Claude 商业版与 ChatGPT Business 成本对比列出了每个方案。把席位成本和一个工作流节省的工时相比时，要把审核人的时间也算进去。

08代理机构应该衡量什么？

按工作流衡量工作本身，前后对比：从简报到初稿的小时数、编辑对每份草稿的改动量、与客户的修改轮次、草稿未通过审核关口的频率，以及包含审核人时间在内的单件交付成本。先记录一个月的基线，否则比较只能靠记忆。

指标它告诉你什么从哪里获取
从简报到初稿的小时数工作流是否节省了时间工时记录，或文件上的时间戳
每份草稿的编辑改动量简报和语调规则是否够好草稿的 git 历史
客户修改轮次质量是否传递到了客户那里你的审批工具

编辑改动量逐渐下降，通常是客户简报开始奏效的最早信号。

09什么时候该请 Claude Code 顾问？

当最初的几个工作流已经跑起来，整套配置却开始吃力时，就该请 Claude Code 顾问了：指令文件互相矛盾，连接器需要写入权限，几位员工需要共用一套技能库，或者客户合同要求有文档记录的数据配置。在此之前，自己动手搭建前两个工作流，学到的东西最多。

好的顾问在你的账户上搭建，把一切写下来，并让你的团队不依赖他们也能运行和修改这套配置。问他们的问题，和你会问一位AI 智能体开发者的问题一样：给我看它运行，给我看测试，文件归谁所有，交接包括什么。公开技能库是在通话之前评判任何人方法的公平途径，我的方法也包括在内。

11简要总结

为每个客户写一份简报，然后依次搭建调研、初稿、审核和报告，一次一个工作流。每个客户放在独立的文件夹和仓库里，配各自的连接器，使用商业版方案，并在工作到达客户或公众之前，在每道关口都安排一个人。

从基线开始衡量工时、改动量和修改轮次，等这套配置超出了运行它的人能承担的范围，再请人帮忙。

12企业主常问的问题

营销代理机构用 Claude Code 做什么？

代理机构用 Claude Code 处理可重复的客户工作：把需求调研笔记整理成客户简报，制作调研资料包，按简报起草内容，针对搜索和 AI 回答审核网站，以及撰写月度报告。智能体负责调研和初稿。每一份内容在客户看到之前，都由代理机构团队里的一个人审核；凡是要发布或发送的内容，都由客户批准。

用 Claude Code 处理客户数据安全吗？

选对方案、配置得当，就可以做到安全。Anthropic 的文档说明，在商业条款下发送给 Claude Code 的代码或提示词不会用于训练生成式模型，商业条款涵盖 Team、Enterprise 和 API 使用。把每个客户放在单独的文件夹里，配各自的连接器，禁止访问敏感文件，并且在客户的个人信息接触任何 AI 工具之前，先做一次隐私影响评估。

代理机构员工需要会写代码才能用 Claude Code 吗？

大部分配置用普通语言写成即可：指令文件、客户简报，以及一步步描述流程的技能文件。员工需要习惯在文件夹里工作，并能看懂智能体改了什么。代码在后期才变得重要，比如报告流水线、图形渲染或自动检查，这些代码 Claude Code 能写出大部分，但团队里应该有人能读懂。

代理机构用 Claude Code 要花多少钱？

在 Claude Team 和 Enterprise 方案下，Claude Code 的用量从每位成员的席位额度中扣除，这份额度与 Claude 聊天共用。通过 API 使用则按 token 计费。Anthropic 的文档显示，企业软件团队平均每位开发者每月约 US$150 到 250。营销用途的情况不同，所以先做一个小规模试点并测量用量，再推广到所有客户账户。

什么是 Claude Code 营销技能？

技能是一个包含 SKILL.md 文件的文件夹，描述一个流程，比如撰写简报、针对 AI 回答审核页面，或者制作月度报告。当技能的描述与任务匹配，或者你按名称调用它时，Claude Code 就会使用这个技能。项目技能可以提交到 git，这样代理机构里每个人运行的都是同一版流程。

代理机构什么时候该请 Claude Code 顾问？

当最初的几个工作流已经跑起来，整套配置却开始吃力时，就该请顾问了：指令文件互相矛盾，连接器需要写入权限，几位员工需要共用一套技能库，或者客户合同要求有文档记录的数据配置。好的顾问会在你自己的账户上搭建，把一切写成文档，并让你的团队能够自行运行和修改。
